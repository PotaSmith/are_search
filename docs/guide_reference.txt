================================================================
AreSearch リファレンス
================================================================

このガイドは、利用側で指定する設定値、mappings/dataの定義、名前制約、公開APIをまとめる。
導入手順は guide_setup.txt、検索方法は guide_usage.txt、IndexTargetとsync stageは guide_index_targets_and_stages.txt、
運用操作と障害対応は guide_operations.txt を参照する。


# 1. 任意設定
================================================================

config/initializers/are_search.rb の AreSearch.setup 後に指定できる。

    AreSearch.sync_request_delay             = 120
    AreSearch.max_sync_try_count             = 100
    AreSearch.sync_request_process_hang_wait = 1800
    AreSearch.max_force_try_count            = 5
    AreSearch.lock_dir                       = Rails.root.join("tmp", "are_search", "locks").to_s
    AreSearch.index_operation_enabled        = false
    AreSearch.rake_operation_enabled         = false
    AreSearch.after_commit_mode              = :direct
    AreSearch.batch_size                     = 500
    AreSearch.search_failure_mode            = :empty_result
    AreSearch.search_body_policy             = AreSearch::ScriptDenySearchBodyPolicy
    AreSearch.search_param_policy            = AreSearch::ParamLengthSearchParamPolicy


## 1-1. sync_request_delay
----------------------------------------------------------------

run_sync_requests が通常の再同期対象にするまでの待機秒数。
デフォルトは120秒。


## 1-2. max_sync_try_count
----------------------------------------------------------------

run_sync_requests が通常同期を試す上限。
デフォルトは100回。


## 1-3. sync_request_process_hang_wait
----------------------------------------------------------------

処理中のまま残った sync request を強制同期対象にするまでの秒数。
デフォルトは1800秒。


## 1-4. max_force_try_count
----------------------------------------------------------------

run_sync_requests が強制同期を試す上限。
デフォルトは5回。


## 1-5. lock_dir
----------------------------------------------------------------

flock ファイルの保存先。

    Rails.root.join("tmp", "are_search", "locks").to_s

配下は用途ごとに分かれる。

    sync/sync.lock
    index/{index_alias_name}.lock

複数プロセスで同じ排他を使用する場合は同じ lock_dir を参照できるようにする。


## 1-6. index_operation_enabled
----------------------------------------------------------------

reindex、clean up、manual marker、物理 index の手動削除などを許可する。
デフォルトは false。

    AreSearch.index_operation_enabled = true

index操作を行うプロセスだけ true にする。


## 1-7. rake_operation_enabled
----------------------------------------------------------------

sync request を回収する are_search:run_sync_requests の実行を許可する。
デフォルトは false。

    AreSearch.rake_operation_enabled = true

定期実行を担当する単一の環境だけ true にする。
共有されていない lock_dir を使用する複数環境からの同時実行は想定しない。


## 1-8. after_commit_mode
----------------------------------------------------------------

DB commit 後の同期開始方法。

    :direct
        after_commit で直接同期する。デフォルト。

    :job
        AreSearch::SyncJob をキューへ追加する。

    :none
        after_commit では同期せず、run_sync_requests に任せる。

どのモードでも通常の保存・削除時には sync request が記録される。
失敗した要求は run_sync_requests で再処理できる。


## 1-9. batch_size
----------------------------------------------------------------

reindex 時に DB から一度に読み込む件数。
デフォルトは500。

    AreSearch.batch_size = 500

小さくすると1回のメモリ使用量と bulk body が減り、DB取得回数とbulk回数が増える。
この設定は reindex にだけ使われる。


## 1-10. analyzer_settings
----------------------------------------------------------------

index 作成時に Elasticsearch の settings へ渡す analyzer 設定。
デフォルトでは以下が定義される。

    cjk_index_analyzer
    cjk_search_analyzer

変更する場合は are_search_index_mappings から参照する analyzer をすべて定義する。
変更後は対象targetの reindex が必要。


## 1-11. search_failure_mode
----------------------------------------------------------------

検索パラメータ不正、検索body policyによる拒否、index不存在を検索時にどう扱うか指定できる。

    :empty_result
        status付きの空結果を返す。ライブラリ側のデフォルト。

    :raise
        原因に対応する例外を送出する。

送出する例外。

    外部入力として使用する検索値の不正
        AreSearch::InvalidSearchOption

    検索body policyによる拒否
        AreSearch::InvalidSearchBody

    index不存在
        AreSearch::SearchIndexNotFound

生成される initializer は development 環境で :raise、それ以外で :empty_result を設定する。


## 1-12. search_body_policy
----------------------------------------------------------------

Elasticsearchへ送信する検索bodyと mapping のフィールド名を検査する policy。
デフォルトは AreSearch::ScriptDenySearchBodyPolicy。

標準policyは script、script_*、*_script に一致するキーを拒否する。

差し替える場合は AreSearch::SearchBodyPolicy を継承する。

    class ApplicationSearchBodyPolicy < AreSearch::SearchBodyPolicy
        def self.valid?(es_params)
            true
        end

        def self.invalid_key?(key_name)
            false
        end
    end

    AreSearch.search_body_policy = ApplicationSearchBodyPolicy

valid? は検索body全体、invalid_key? は mapping のフィールド名を検査する。


## 1-13. search_param_policy
----------------------------------------------------------------

外部入力として扱う検索パラメータの値を検査する policy。
デフォルトは AreSearch::ParamLengthSearchParamPolicy。

標準policyの上限。

    queries.query_string
        2048文字

    where / where_not / where_or の term の値
        256文字

    where / where_not / where_or の terms の Array 全体
        256文字

    where / where_not / where_or の range の Hash 全体
        256文字

既定の制限を一部変更する場合。

    class ApplicationSearchParamPolicy < AreSearch::ParamLengthSearchParamPolicy
        def self.valid?(name, value)
            return value.to_s.length <= 4096 if name == "query_string"

            super
        end
    end

    AreSearch.search_param_policy = ApplicationSearchParamPolicy

false を返した値は AreSearch::InvalidSearchOption として扱う。


# 2. index_settings
================================================================

index_settings は are_search_index_mappings の target ごとに指定する。
定義例は「3. are_search_index_mappings」を参照する。
Elasticsearch の index 設定を指定できる。


## 2-1. max_result_window
----------------------------------------------------------------

page / per_page で取得できる範囲の上限。
複数target検索では対象targetの最小値を使用する。

page と per_page から算出した開始位置が max_result_window 以上の場合は検索パラメータ不正になる。
設定変更後は reindex が必要。


# 3. are_search_index_mappings
================================================================

クラスメソッドで index_target_name ごとの定義を返す。

    def self.are_search_index_mappings
        {
            default: {
                index_settings: {
                    max_result_window: 2_000,
                },
                _source: {
                    includes: [:title],
                },
                properties: {
                    id:    { type: "long" },
                    title: { type: "text" },
                },
            },
        }
    end

注意点。

    _source.enabled に false は指定できない
    field_name は検索body policyでも検査する

元のフィールド値を _source 以外から取得する機能で使用する場合は store: true を指定できる。

    body: {
        type:  "text",
        store: true,
    }

STIでは Searchable を持つ継承系統の上位モデルで定義する。


# 4. are_search_index_data
================================================================

インスタンスメソッドで、targetとstageの組み合わせに投入する完成ドキュメントを返す。

    def are_search_index_data(index_target_name, sync_stage_name)
        case [index_target_name, sync_stage_name]
        when [:default, "default"]
            {
                id:    id,
                title: title,
            }
        else
            {}
        end
    end

各stageは部分更新ではなく完成ドキュメント全体を返す。


# 5. are_search_indexable?
================================================================

レコードをtarget・stageごとに index するか指定できる。
デフォルトは true。

    def are_search_indexable?(index_target_name, sync_stage_name)
        case [index_target_name, sync_stage_name]
        when [:default, "default"]
            published?
        else
            true
        end
    end

同期対象にしない場合は false を返す。
その target の検索対象から外す用途で使用する。


# 6. IndexTarget の主な公開API
================================================================

IndexTarget を取得する。

    article_index = Article.are_search_index_target(:default)

主な操作。

    article_index.are_search_search("Rails", fields: [:title, :body])
    article_index.are_search_index_marked?
    article_index.are_search_index_alias_exists?
    article_index.are_search_reindex(stage_position: :first)
    article_index.are_search_clean_up
    article_index.are_search_with_index_guard(operation: "batch") do
        # IndexTarget単位で排他した処理
    end
    article_index.are_search_delete!(article.id)

stageを使用する直接操作。

    article.are_search_index_or_delete!(
        article_index,
        "default",
    )


## 6-1. index 操作の戻り値
----------------------------------------------------------------

are_search_reindex、are_search_clean_up、are_search_with_index_guard の戻り値は結果を表す Hash。

    result       成否。:success または :not_success。
    message      失敗理由。
    failed_ids   失敗したレコードID。対象操作でのみ含まれる。
    stop_phase   停止した処理段階。成功時は nil。
    done_phases  完了した処理段階。

# 7. コールバックを通らない更新用API
================================================================

通常saveと同じ同期経路へ乗せる場合は、DB更新と are_search_enqueue_sync_request を同じトランザクション内で行い、
commit後に are_search_after_commit を呼ぶ。

    article = Article.find(id)

    Article.transaction do
        article.update_columns(
            title:      "変更後のタイトル",
            updated_at: Time.zone.now,
        )

        article.are_search_enqueue_sync_request
    end

    article.are_search_after_commit

update_all、delete_all、insert_all、upsert_all など複数件を変更する場合は、対象レコードごとに同期要求を作成するか、
件数に応じて reindex を使用する。


# 8. are_search_with_index_guard
================================================================

対象 IndexTarget の index 操作と競合させたくない直接更新を guard 内で実行する。

    index_target = Article.are_search_index_target(:default)

    result = index_target.are_search_with_index_guard(
        operation: "pdf_extract",
    ) do
        article.are_search_index_or_delete!(index_target, "default")

        :done
    end

実行後は result[:result] を確認する。

operation は状態確認時に処理を識別するための名前として指定する。
この処理には AreSearch.index_operation_enabled = true が必要。
詳細な運用例は guide_operations.txt を参照する。


# 9. 低レベル操作
================================================================


## 9-1. are_search_index_or_delete!
----------------------------------------------------------------

レコードの現在状態を直接 Elasticsearch へ反映する。

    index_target = Article.are_search_index_target(:default)

    if index_target.are_search_index_alias_exists?
        article.are_search_index_or_delete!(index_target, "default")
    end

sync request を経由しないため、通常の再試行経路が必要な処理では使用しない。


## 9-2. are_search_delete!
----------------------------------------------------------------

ドキュメントを直接削除する。

    index_target = Article.are_search_index_target(:default)

    if index_target.are_search_index_alias_exists?
        index_target.are_search_delete!(id)
    end

対象が存在しない場合は無視する。


## 9-3. 物理 index の手動削除
----------------------------------------------------------------

    AreSearch.delete_physical_index!(physical_index_name)

AreSearch.index_operation_enabled = true が必要。
通常は clean up を使用し、手動削除は状態を確認したうえで行う。


# 10. 利用側定義名
================================================================

AreSearch は次の名前を共通形式で検査する。

    index_prefix
    are_search_ar_table_name
    index_target_name
    are_search_index_mappings の field_name
    sync_stage_name

共通形式。

    小文字英字で始める
    各単語には小文字英数字を使用する
    複数の単語は単一のアンダーバーで区切る

使用できる例。

    article
    article2
    article_v2
    field_2026

使用できない例。

    Article
    2article
    _article
    article_
    article__body
    article-body

型。

    index_prefix
        String。空文字列は使用できない。

    are_search_ar_table_name
        String。

    index_target_name
        Symbol。

    field_name
        Symbol。

    sync_stage_name
        String。

Searchableモデルの静的定義は最初に are_search_index_targets を取得するときに検査する。
are_search:check_all_models でも同じ定義検査を行う。

# 11. SyncRequest の状態項目
================================================================

are_search_sync_requests の主な状態項目。

    request_sequence / request_sequence_at      同期要求の世代とその時刻。
    processing_token / processing_at            処理中を示す識別値とその時刻。
    sync_try_count / last_sync_try_at            通常同期の試行回数と最終試行時刻。
    callback_try_count / last_callback_try_at    同期後callbackの試行回数と最終試行時刻。
    last_completed_at                            最後に同期要求全体が完了した時刻。
    force_attempted / force_try_count / last_force_try_at  force同期の有無、試行回数、最終試行時刻。
    last_error / last_error_at                    最後のエラー内容とその記録時刻。
