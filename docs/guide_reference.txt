================================================================
AreSearch リファレンス
================================================================

このガイドは、利用側で指定する設定値、mappings/dataの定義、名前制約、操作をまとめる。
利用者が設定または操作したときに AreSearch が行う処理を記載する。
導入手順は guide_setup.txt、検索方法は guide_usage.txt、IndexTargetとsync stageは guide_index_targets_and_stages.txt、
運用操作、障害対応、block形式の操作例は guide_operations.txt を参照する。


# 1. 設定
================================================================

Elasticsearch client と index_prefix は AreSearch.setup で指定する。
その他の設定は AreSearch.setup の前後に関係なく指定できる。

    AreSearch.sync_request_delay             = 120
    AreSearch.max_sync_try_count             = 100
    AreSearch.sync_request_process_hang_wait = 1800
    AreSearch.max_force_try_count            = 5
    AreSearch.lock_dir                       = Rails.root.join("tmp", "are_search", "locks").to_s
    AreSearch.index_operation_enabled        = false
    AreSearch.rake_operation_enabled         = false
    AreSearch.after_commit_mode              = :direct
    AreSearch.batch_size                     = 500
    AreSearch.search_failure_mode            = :empty_result
    AreSearch.search_body_policy             = AreSearch::ScriptDenySearchBodyPolicy
    AreSearch.search_param_policy            = AreSearch::SearchParamLengthPolicy
    AreSearch.analyzer_settings              = AreSearch.analyzer_settings
    AreSearch.logger                         = Rails.logger
    AreSearch.database_specific              = AreSearch::PostgreSQLDatabaseSpecific
    AreSearch.searchable_class_setting       = {}


## 1-1. setup
----------------------------------------------------------------

Elasticsearch client の作成方法と index_prefix を指定する。

    AreSearch.setup(index_prefix: "example_production") do
        Elasticsearch::Client.new(...)
    end

ブロックが返した Elasticsearch::Client を AreSearch.client として使用する。
index_prefix は IndexTarget の alias 名と物理 index 名の先頭要素に使用する。


## 1-2. sync_request_delay
----------------------------------------------------------------

run_sync_requests が通常の再同期対象にするまでの待機秒数。
デフォルトは120秒。


## 1-3. max_sync_try_count
----------------------------------------------------------------

run_sync_requests が通常同期を試す上限。
デフォルトは100回。


## 1-4. sync_request_process_hang_wait
----------------------------------------------------------------

処理中のまま残った sync request を force 同期の対象として扱うまでの秒数。
デフォルトは1800秒。

force 同期では同期本体を実行し、同期後callbackは実行しない。
処理した要求は force_attempted に記録し、通常の run_sync_requests で回収する。


## 1-5. max_force_try_count
----------------------------------------------------------------

run_sync_requests が強制同期を試す上限。
デフォルトは5回。


## 1-6. lock_dir
----------------------------------------------------------------

index lock と run_sync_requests の多重起動防止用lockファイルの保存先。

    Rails.root.join("tmp", "are_search", "locks").to_s

配下は用途ごとに分かれる。

    sync_runner/sync_runner.lock
    index/{index_alias_name}.lock

複数の処理で同じ排他を使用する場合は同じ lock_dir を参照できるようにする。


## 1-7. index_operation_enabled
----------------------------------------------------------------

reindex、clean up、manual sync lock、物理 index の手動削除などを許可する。
デフォルトは false。

    AreSearch.index_operation_enabled = true

index操作を行う実行環境だけ true にする。


## 1-8. rake_operation_enabled
----------------------------------------------------------------

are_search:run_sync_requests や Boundary操作用 などの
SyncRequestを操作するrake処理の実行を許可する。

デフォルトは false。

    AreSearch.rake_operation_enabled = true

定期実行を担当する単一の環境だけ true にする。
共有されていない lock_dir を使用する複数環境からの同時実行は想定しない。


## 1-9. after_commit_mode
----------------------------------------------------------------

DB commit 後の同期開始方法。

    :direct
        after_commit で直接同期する。デフォルト。

    :job
        AreSearch::SyncJob をキューへ追加する。

    :none
        after_commit では同期せず、run_sync_requests に任せる。

どのモードでも通常の保存・削除時には sync request を記録する。
after_commit からの同期またはJobで同期が完了しなかった要求は、run_sync_requests で再度同期対象として扱う。


## 1-10. batch_size
----------------------------------------------------------------

reindex 時に DB から一度に読み込む件数。
デフォルトは500。

    AreSearch.batch_size = 500

小さくすると1回のメモリ使用量と bulk body が減り、DB取得回数とbulk回数が増える。
この設定は reindex にだけ使われる。


## 1-11. analyzer_settings
----------------------------------------------------------------

index 作成時に Elasticsearch の settings へ渡す analyzer 設定。
デフォルトでは以下が定義される。

    cjk_index_analyzer
    cjk_search_analyzer

変更する場合は properties_method が返す field 定義から参照する analyzer をすべて定義する。
変更後は対象targetの reindex が必要。

analyzer_settings は :analysis を持つ Hash で指定する。


## 1-12. search_failure_mode
----------------------------------------------------------------

検索パラメータ不正、検索body policyによる拒否、index不存在を検索時にどう扱うか指定できる。

    :empty_result
        status付きの空結果を返す。ライブラリ側のデフォルト。

    :raise
        原因に対応する例外を送出する。

:raise の場合に発生する例外

    外部入力として使用する検索値の不正
        AreSearch::InvalidSearchOption

    検索body policyによる拒否
        AreSearch::InvalidSearchBody

    alias が存在しない、または状態確認に失敗した場合
        AreSearch::SearchIndexNotFound

    それ以外
        発生元の例外そのまま

:empty_result の場合の status

    guide_usage の SearchResult を参照

生成される initializer は development 環境で :raise、それ以外で :empty_result を設定する。


## 1-13. search_body_policy
----------------------------------------------------------------

Elasticsearchへ送信する検索bodyと mapping のフィールド名を検査する policy。
ただし、runtime_mappings は対象外。

デフォルトは AreSearch::ScriptDenySearchBodyPolicy。

標準policyは script、script_*、*_script に一致するキーを拒否する。

差し替える場合は AreSearch::SearchBodyPolicy を継承する。

    class ApplicationSearchBodyPolicy < AreSearch::SearchBodyPolicy
        def self.valid?(es_params)
            true
        end

        def self.invalid_key?(key_name)
            false
        end
    end

    AreSearch.search_body_policy = ApplicationSearchBodyPolicy

valid? は検索body全体、invalid_key? は mapping のフィールド名を検査する。


## 1-14. search_param_policy
----------------------------------------------------------------

外部入力として扱う検索パラメータの値を検査する policy。
デフォルトは AreSearch::SearchParamLengthPolicy。

標準policyの上限。

    queries.query_string
        2048文字

    where / where_not / where_or の term の値
        128文字
    where / where_not / where_or の terms の Array 全体
        1024文字
    where / where_not / where_or の range の Hash 全体
        256文字

差し替える場合は AreSearch::SearchParamPolicy を継承する。

    class ApplicationSearchParamPolicy < AreSearch::SearchParamPolicy
        def self.check_value(name, value)
            if value.to_s.length > 4096
                "検索値は4096文字以内で指定してください"
            else
                nil
            end
        end
    end

    AreSearch.search_param_policy = ApplicationSearchParamPolicy

check_value は、問題がある場合はエラーメッセージ、問題がない場合は nil を返す。


## 1-15. logger
----------------------------------------------------------------

AreSearch が使用する logger を指定する。

    AreSearch.logger = Rails.logger

未指定の場合は Rails.logger を使用する。


## 1-16. database_specific
----------------------------------------------------------------

sync request の採番と登録で使用するDB固有処理を指定する。
デフォルトは AreSearch::PostgreSQLDatabaseSpecific。

別実装を使用する場合は AreSearch::DatabaseSpecific を継承する。

    class ApplicationDatabaseSpecific < AreSearch::DatabaseSpecific
        def self.next_request_sequence
            # 利用DBに合わせて採番する
        end

        def self.upsert(**attributes)
            # 利用DBに合わせてsync requestを登録または更新する
        end
    end

    AreSearch.database_specific = ApplicationDatabaseSpecific


# 2. searchable_class_setting
================================================================

Searchableモデルの IndexTarget・sync stage 構成は AreSearch.searchable_class_setting へまとめて指定する。
生成される config/are_search_searchable.rb.sample を config/are_search_searchable.rb に変更し
config/are_search_searchable.rb に定義する。
生成される config/initializers/are_search.rb の先頭からこのファイルを読み込む。

    AreSearch.searchable_class_setting = {
        "Article" => {
            default: {
                index_target_name_alias: :current,
                settings: {
                    max_result_window: 2_000,
                },
                mappings: {
                    _source: {
                        includes: [:title],
                    },
                },
                properties_method: :default_properties,
                indexable_method: :default_indexable?,
                stages: {
                    "default" => {
                        data_method: :default_search_data,
                        enqueue: true,
                        after_commit: true,
                    },
                },
            },
            _callbacks: {
                before_sync_check: :default_before_sync_check,
                after_sync_callback: :default_after_sync_callback,
            },
        },
    }

トップレベルのkeyはモデルクラス名の String。
モデル設定内では IndexTarget 名を Symbol で指定し、_callbacks だけを予約keyとして使用する。

Rails の after_initialize で searchable_class_setting 全体を検査する。
STIでは Searchable を include した継承系統の上位モデルだけを設定し、子クラスはその設定を使用する。


## 2-1. index_target_name_alias
----------------------------------------------------------------

IndexTargetを別名から取得する場合に指定する。省略できる。

    index_target_name_alias: :current

取得する。

    Article.are_search_index_target_alias(:current)

同じモデル設定内で alias 名は重複できない。


## 2-2. settings
----------------------------------------------------------------

Elasticsearch index の settings を Hash で指定する。必須。
analysis は AreSearch.analyzer_settings を使用するため、ここでは指定できない。

    settings: {
        max_result_window: 2_000,
    }

max_result_window は正の Integer で指定する。
複数target検索では対象targetの最小値を使用する。
設定変更後は対象targetを reindex して新しい設定を使用する。


## 2-3. mappings
----------------------------------------------------------------

properties 以外の Elasticsearch mappings を Hash で指定する。
省略可能。
properties は properties_method の戻り値を使用するため、ここでは指定できない。

    mappings: {
        _source: {
            includes: [:title],
        },
    }

Hash key は Symbol で指定する。
_source.enabled に false は指定できない。

AreSearch は検索 index の容量削減と ActiveRecord 復元のため、
_source.includes に予約フィールドを必ず追加する。
_source.includes を指定しない場合も予約フィールドだけの includes を設定する。

利用側のフィールドを _source に保存する場合は、includes へ明示する。

_source.includes を指定しない場合、excludes は予約フィールドだけの
includes に対する除外となり、通常はほとんど意味をなさない。
指定は可能だが注意が必要。
ActiveRecord 復元用の予約フィールドは excludes に指定しない。


## 2-4. properties_method
----------------------------------------------------------------

IndexTarget の properties を返す、引数なしのクラスメソッド名を指定する。必須。

    properties_method: :default_properties

    def self.default_properties
        {
            id:    { type: "long" },
            title: { type: "text", store: true },
        }
    end

戻り値は Hash。field_name と Hash key は Symbol で指定する。
各fieldには :type が必要。field_name は search body policy でも検査する。
STI 子クラスでは properties_method をオーバーライドできない。

元のフィールド値を _source 以外から取得する mlt のような機能で使用する場合は

    store: true

を指定できる。


## 2-5. indexable_method
----------------------------------------------------------------

その IndexTarget へレコードを index するか返す、引数なしのインスタンスメソッド名を指定する。
省略可能。省略した場合はすべてのレコードをindex対象にする。

    indexable_method: :default_indexable?

    def default_indexable?
        published?
    end

false の場合は IndexTarget からdeleteする。
indexable_method を省略した場合は、すべてのレコードを index 対象にする。
indexable_method は IndexTarget 単位であり、stageごとには分かれない。

gem は unscoped でレコードを取得するため、除外が必要であればここに条件を指定する。


## 2-6. stages
----------------------------------------------------------------

IndexTargetで使用する sync stage を Hash で設定順に定義する。1件以上必要。

    stages: {
        "default" => {
            data_method: :default_search_data,
            enqueue: true,
            after_commit: true,
        },
        "with_external_file" => {
            data_method: :with_external_file_search_data,
            enqueue: true,
            after_commit: false,
        },
    }

各stageには data_method、enqueue、after_commit が必要。

    data_method
        完成ドキュメントを返す引数なしのインスタンスメソッド名。

    enqueue
        保存・touch・削除時に SyncRequest を作る場合は true。

    after_commit
        commit後に direct 同期またはJob登録を開始する場合は true。
        true の場合は enqueue も true にする。

stageの定義順は reindex の stage_position: :first / :last で使用する。


## 2-7. data_method
----------------------------------------------------------------

data_method は、指定stageへ投入する完成ドキュメント全体を Hash で返す。

    def default_search_data
        {
            id:    id,
            title: title,
        }
    end

各stageは部分更新ではない。
複数stageで同じ完成ドキュメントを使用する場合は、同じ data_method を指定できる。


## 2-8. _callbacks
----------------------------------------------------------------

モデル単位の同期callbackを指定する。省略できる。

    _callbacks: {
        before_sync_check: :default_before_sync_check,
        after_sync_callback: :default_after_sync_callback,
    }

指定するメソッドはいずれもクラスメソッドで、3引数を受け取る。

    def self.default_before_sync_check(ar_instance_key, index_target, sync_request)
        ready?
    end

false の間はその要求の同期を開始しない。

    def self.default_after_sync_callback(record, index_target, sync_request)
        return if record.nil?

        record.are_search_upsert_sync_request(
            index_target,
            "next_stage",
        )
    end

are_search_upsert_sync_request は指定した IndexTarget・stage の sync request を登録または更新する。


## 2-9. sync stage とコールバック
----------------------------------------------------------------

保存時・after_commit の対象は stages 内の enqueue / after_commit でstageごとに指定する。
重いstageをrakeへ残す場合は enqueue: true、after_commit: false にする。

指定したsync requestが存在するか確認する場合は are_search_sync_request_exists? を使用する。

    Article.are_search_sync_request_exists?(
        article.id,
        index_target,
        "default",
    )


# 3. IndexTarget の操作
================================================================

IndexTarget を取得する。

    article_index = Article.are_search_index_target(:default)

全targetを取得する。

    Article.are_search_index_targets

IndexTargetからalias名、index設定、mappingを取得できる。

    article_index.are_search_index_alias_name
    article_index.are_search_index_settings
    article_index.are_search_index_mappings

主な操作。

    article_index.are_search_search("Rails", fields: [:title, :body])
    article_index.are_search_index_target_syncable?
    article_index.are_search_processing_sync_request_exists?
    article_index.are_search_processing_sync_stage_sync_request_exists?("default")
    article_index.are_search_index_alias_exists?
    article_index.are_search_create_index
    article_index.are_search_reindex(stage_position: :first)
    article_index.are_search_clean_up
    article_index.are_search_bulk_index(
        "default",
        result_dir: result_dir,
        max_bulk_bytes: 20 * 1024 * 1024,
        max_bulk_count: 100,
        max_fail_count: 100,
    )
    article_index.are_search_delete!(article.id)

are_search_create_index は、その IndexTarget 用の空の物理indexを作成してaliasを接続する。
既存データを投入する場合は、その後に reindex または BulkIndexer を実行する。

are_search_bulk_index は、指定stageの完成ドキュメントを既存aliasへbulk投入する。
recover: true を指定すると、同じ result_dir に記録された未解決の失敗IDを再処理する。

are_search_processing_sync_request_exists? は、そのIndexTargetで processing_token を持つSyncRequestが存在するか返す。
are_search_processing_sync_stage_sync_request_exists? は、指定stageに限定して同じ確認を行う。

stageを使用する直接操作。

    article.are_search_index_or_delete!(
        article_index,
        "default",
    )


## 3-1. index 操作の戻り値
----------------------------------------------------------------

are_search_reindex、are_search_clean_up の戻り値は処理結果を表す Hash。

    result       :success または :not_success。
    message      処理結果の説明。
    stop_phase   処理を終了した段階。完了時は nil。
    done_phases  完了した処理段階。

操作によっては、失敗したレコードIDや削除対象の index 名など、追加の結果情報が含まれる。
処理中に例外が発生した場合は、Hashを返さず例外を送出することがあります。


# 4. コールバックを通らない更新
================================================================

通常saveと同じ同期経路へ乗せる場合は、DB更新と are_search_enqueue_sync_request を同じトランザクション内で行い、
commit後に are_search_after_commit を呼ぶ。

    article = Article.find(id)

    Article.transaction do
        article.update_columns(
            title:      "変更後のタイトル",
            updated_at: Time.zone.now,
        )

        article.are_search_enqueue_sync_request
    end

    article.are_search_after_commit

update_all、delete_all、insert_all、upsert_all など複数件を変更する場合は、対象レコードごとに同期要求を作成するか、
件数に応じて reindex を使用する。


# 5. block形式の操作
================================================================

block形式の操作は、処理中だけsync stage sync lockを取得する。
使用例と組み合わせ方は guide_operations.txt を参照する。

AreSearch.index_operation_enabled = true が必要。
operation には状態確認時に処理を識別する名前を指定する。


## 5-1. are_search_with_sync_stage_lock
----------------------------------------------------------------

    are_search_with_sync_stage_lock(sync_stage_name, operation:) { ... }

指定stageの sync stage sync lock を取得してblockを実行する。
blockの戻り値を返す。


# 6. 直接操作
================================================================


## 6-1. are_search_index_or_delete!
----------------------------------------------------------------

レコードの現在状態を直接 Elasticsearch へ反映する。

    index_target = Article.are_search_index_target(:default)

    if index_target.are_search_index_alias_exists?
        article.are_search_index_or_delete!(index_target, "default")
    end

sync request を経由しないため、通常の再試行経路が必要な処理では使用しない。


## 6-2. are_search_delete!
----------------------------------------------------------------

ドキュメントを直接削除する。

    index_target = Article.are_search_index_target(:default)

    if index_target.are_search_index_alias_exists?
        index_target.are_search_delete!(id)
    end

対象が存在しない場合は無視する。


## 6-3. 物理 index の手動削除
----------------------------------------------------------------

    AreSearch.delete_physical_index!(physical_index_name)

AreSearch.index_operation_enabled = true が必要。
通常は clean up を使用し、手動削除は状態を確認したうえで行う。


## 6-4. manual sync lock
----------------------------------------------------------------

index target sync lock と sync stage sync lock は排他ではない。
同期処理では index target sync lock が全 sync stage を対象とする上位の lock として機能する。

manual sync lock は、DB側から同期処理の開始を止める。
IndexTarget全体を対象にする index target sync lock がある。
特定stageだけを対象にする sync stage sync lock もある。

設定する。

    index_target = Article.are_search_index_target(:default)
    sync_stage_name = "with_external_file"

    index_target.are_search_acquire_sync_lock!
    index_target.are_search_acquire_sync_stage_lock!(sync_stage_name)

同じ対象に既存lockがある場合は新しいlockを作成せず nil を返す。
index target sync lock と sync stage sync lock は別のlockとして共存できる。

通常解除する。

    index_target.are_search_release_sync_lock!
    index_target.are_search_release_sync_stage_lock!(sync_stage_name)

通常解除は operation が manual のlockだけを削除する。

通常解除で残留lockを解除できない場合は、状態を確認したうえで強制解除する。

    index_target.are_search_force_release_sync_lock!
    index_target.are_search_force_release_sync_stage_lock!(sync_stage_name)

強制解除は operation や所有者に関係なく対象lockを削除する。
状態は are_search:check_index_status と are_search:check_sync_request_status で確認できる。
全targetの index target sync lock の設定・解除には、次の rake task を使用する。

    are_search:acquire_sync_lock_all
    are_search:release_sync_lock_all

AreSearch.index_operation_enabled = true が必要。


## 6-5. are_search_index_data_validate
----------------------------------------------------------------

レコードについて、各 IndexTarget・stage の are_search_index_data と mappings の整合性を確認する。

    article.are_search_index_data_validate

確認結果は article.errors から参照する。


# 7. 利用側定義名
================================================================

AreSearch は次の名前を共通形式で検査する。

    index_prefix
    are_search_ar_table_name
    index_target_name
    properties_method が返す field_name
    sync_stage_name

共通形式。

    小文字英字で始める
    各単語には小文字英数字を使用する
    複数の単語は単一のアンダーバーで区切る

使用できる例。

    article
    article2
    article_v2
    field_2026

使用できない例。

    Article
    2article
    _article
    article_
    article__body
    article-body

型。

    index_prefix
        String。空文字列は対象外。

    are_search_ar_table_name
        String。

    index_target_name
        Symbol。

    field_name
        Symbol。

    sync_stage_name
        String。

are_search_ar_table_name はデフォルトで Active Record の table_name を使用する。
別の名前を使用する場合はクラスメソッドで指定する。

    def self.are_search_ar_table_name
        "articles"
    end

この値は IndexTarget の alias 名と物理 index 名の要素に使用する。

Searchableモデルの設定は Rails の after_initialize で検査する。
are_search:check_all_models では STI 子クラスで解決される設定メソッドも含めて確認する。


# 8. SyncRequest の状態確認
================================================================

rakeで同期要求を回収するときは、are_search_sync_requests の状態項目を確認できる。

    request_sequence / request_sequence_at
        同期要求の世代と、その要求が発生または更新された時刻を確認する。

    processing_token / processing_at
        現在処理対象として扱われているかと、その処理開始時刻を確認する。

    sync_try_count / last_sync_try_at
        通常同期を試行した回数と、最後に試行した時刻を確認する。
        同期要求の処理完了時に試行情報をリセットする。

    callback_try_count / last_callback_try_at
        同期後callbackを試行した回数と、最後に試行した時刻を確認する。
        同期要求の処理完了時に試行情報をリセットする。

    last_completed_at
        最後に同期要求全体の処理を完了した時刻を確認する。

    force_attempted / force_try_count / last_force_try_at
        force同期を行ったか、試行回数、最後に試行した時刻を確認する。
        force_attempted が記録された要求は、通常の run_sync_requests で回収対象として扱う。

    last_error / last_error_at
        最後に記録されたエラー内容と、その記録時刻を確認する。
        同期要求の処理完了時に記録をクリアする。


# 9. 補助操作
================================================================

設定済みの index_prefix と Elasticsearch client を取得する。

    AreSearch.index_prefix
    AreSearch.client

簡易aggregationで使用する既定のbucket数を取得する。

    AreSearch.default_aggs_size

標準検索の query_type を指定する値を取得する。

    AreSearch.query_type_combined_fields
    AreSearch.query_type_simple_query_string

AreSearch の区切り規則で index 名の要素を連結する。

    AreSearch.join_index_name(
        AreSearch.index_prefix,
        "articles",
        "*",
    )
