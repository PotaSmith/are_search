AreSearch IndexTarget・sync stage ガイド
================================================================

このファイルは、IndexTarget と sync stage の役割、設定、同期・reindex・rakeとの関係を扱う。
導入手順は guide_setup.txt、運用操作は guide_operations.txt、設定と内部動作は guide_reference.txt を参照する。


# 1. IndexTarget と sync stage の関係
================================================================

AreSearch では、同期先を次の2段階で識別する。

    IndexTarget
        Elasticsearch の alias、mappings、index_settings、検索用途を表す。

    sync stage
        同じ IndexTarget へ投入する完成ドキュメントの生成経路を表す。

IndexTarget を変えると、別の Elasticsearch index へ同期する。
sync stage を変えても Elasticsearch index は変わらず、同じ IndexTarget の同じドキュメントIDへ index する。

判断基準。

    別の mappings、analyzer、検索入口、切り替え対象にしたい
        IndexTarget を分ける。

    同じ index だが、データ生成の時期や取得元を分けたい
        sync stage を分ける。

stage は部分更新のフィールド集合ではない。
各stageの are_search_index_data は、そのstageで Elasticsearch へ保存するドキュメント全体を返す。
後続stageが一部のフィールドだけを返すと、それ以前のstageが保存した他のフィールドは消える。


# 2. IndexTarget
================================================================

IndexTarget は、are_search_index_mappings の index_target_name ごとに作成される。

index_target_name は Symbol で定義する。
名前は guide_reference.txt の「利用側定義名」にある共通形式に従う。

    def self.are_search_index_mappings
        {
            default: {
                index_settings: {
                    max_result_window: 2_000,
                },
                properties: {
                    id:    { type: "long" },
                    title: { type: "text" },
                },
            },
            autocomplete: {
                index_settings: {
                    max_result_window: 2_000,
                },
                properties: {
                    id:         { type: "long" },
                    title_edge: { type: "text" },
                },
            },
        }
    end

IndexTarget を取得する。

    default_index = Article.are_search_index_target(:default)
    autocomplete_index = Article.are_search_index_target(:autocomplete)

alias 名は次の形式になる。

    {index_prefix}__{are_search_ar_table_name}__{index_target_name}

独立した Searchable 継承系統で同じ alias 名を使用することはできない。
`are_search:check_all_models` と全reindexの対象作成時に重複を検出した場合はエラーにする。
同じ継承系統のSTI親子・兄弟は、上位モデルが定義した同じIndexTargetを共有する。

1つのモデルに複数targetを定義すると、targetごとに次が分かれる。

    mappings
    index_settings
    aliasと物理index
    reindex
    sync request
    検索入口

モデル更新時に同期要求を作るtargetが増えるため、必要な用途だけ定義する。

検索改善のためにmappingsやanalyzerを変更する場合、使用中targetを直接変更せず、
新しいtargetを追加して新旧indexを並行同期できる。
検索入口を新targetへ切り替え、問題があれば同期され続けている旧targetへ戻せる。


# 3. sync stage
================================================================

sync stage は、IndexTarget 内のデータ生成経路を String で識別する。
sync_stage_name は guide_reference.txt の「利用側定義名」にある共通形式に従う。

    "default"
    "with_external_file"

sync_stage_name は Elasticsearch index 名には含まれない。
同じIndexTarget・同じレコードの各stageは、同じaliasとドキュメントIDへ index する。

例えば、通常のDBカラムだけで作るstageと、外部ファイルを読み込むstageを分けられる。

    def are_search_index_data(index_target_name, sync_stage_name)
        case [index_target_name, sync_stage_name]
        when [:default, "default"]
            {
                id:       id,
                title:    title,
                fulltext: "",
            }
        when [:default, "with_external_file"]
            {
                id:       id,
                title:    title,
                fulltext: get_external_file_text,
            }
        else
            {}
        end
    end

どちらのstageも、mappingsのpropertiesに対応する完成ドキュメント全体を返している。

stage名はtarget内で重複できない。
同じstage名を複数targetで使うことはできる。


# 4. stage の基本設定
================================================================

全stageを `are_search_all_sync_stage_names` で定義する。
このメソッドは必須。

    def self.are_search_all_sync_stage_names
        {
            default: ["default", "with_external_file"],
            autocomplete: ["default"],
        }
    end

制約。

    戻り値は Hash
    key は are_search_index_mappings に存在する index_target_name
    are_search_index_mappings の全targetを定義する
    value は sync_stage_name の Array
    各targetに1件以上のstageを定義する
    sync_stage_name は利用側定義名の共通形式に従う String
    同じtarget内でsync_stage_nameを重複させない

Arrayの順序は、stageを列挙するときと、reindexでfirstまたはlastを選ぶときに使用する。
この順序だけで、前stageの完了待ちや自動的なstage連鎖が行われるわけではない。

運用中にstageを削除しても、そのstageの既存SyncRequestは自動削除しない。
同期時に現在の設定へ存在しないstageを検出した場合は実行せず、`sync_stage_name not found` を記録して要求を残す。
stage廃止時に残存要求を削除または別stageへ移行するかは、利用側で判断する。


# 5. 保存時に作成する要求
================================================================

保存・touch・削除時にsync requestを作成するstageを、`are_search_sync_stage_names_on_enqueue` で指定する。
省略した場合は `are_search_all_sync_stage_names` と同じ設定を使用する。

全stageの要求を作る場合は定義不要。

一部だけ作る場合。

    def self.are_search_sync_stage_names_on_enqueue
        {
            default: ["default"],
            autocomplete: ["default"],
        }
    end

制約。

    are_search_all_sync_stage_names の部分集合
    targetを省略した場合、そのtargetでは保存時に要求を作らない
    空Arrayを指定した場合も、そのtargetでは要求を作らない

保存callbackでは、対象となる `IndexTarget × sync_stage_name` ごとに独立したSyncRequestをupsertする。
SyncRequestの同期キーは次の組み合わせ。

    ar_model_class_name
    ar_instance_key
    index_alias_name
    sync_stage_name

同じindex・モデル・レコードでも、stageごとに別のSyncRequestを保持する。


# 6. after_commit で開始するstage
================================================================

commit後に直接同期またはJob登録を開始するstageを、`are_search_sync_stage_names_on_after_commit` で指定する。
省略した場合は `are_search_all_sync_stage_names` と同じ設定を使用する。

    def self.are_search_sync_stage_names_on_after_commit
        {
            default: ["default"],
            autocomplete: ["default"],
        }
    end

制約。

    are_search_sync_stage_names_on_enqueue の部分集合
    targetを省略した場合、そのtargetではafter_commitから同期を開始しない
    空Arrayを指定した場合も、そのtargetでは同期を開始しない

実際の開始方法は `AreSearch.after_commit_mode` に従う。

    :direct
        指定stageをその場で同期する。

    :job
        指定stageのSyncJobを登録する。

    :none
        after_commitでは開始しない。sync requestはrake回収まで残る。

保存時に要求を作るstageと、commit直後に開始するstageを分けられる。
例えば、軽いstageだけをafter_commitで処理し、重いstageをrakeへ残せる。


# 7. are_search_index_data と are_search_indexable?
================================================================

`are_search_index_data` は index_target_name と sync_stage_name を受け取る。

    def are_search_index_data(index_target_name, sync_stage_name)
        case [index_target_name, sync_stage_name]
        when [:default, "default"]
            {
                id:       id,
                title:    title,
                fulltext: "",
            }
        when [:default, "with_external_file"]
            {
                id:       id,
                title:    title,
                fulltext: get_external_file_text,
            }
        else
            {}
        end
    end

各組み合わせの戻り値は Hash。
トップレベルキーはSymbolとし、そのIndexTargetのpropertiesと揃える。
予約フィールドはAreSearchが追加するため、利用側dataには含めない。

targetやstageが増えて分岐が多くなる場合、`are_search_index_data` は組み合わせの分岐だけを担当し、
実際のデータ生成は通常のモデルメソッドへ分けてもよい。

    def are_search_index_data(index_target_name, sync_stage_name)
        case [index_target_name, sync_stage_name]
        when [:default, "default"]
            std_data
        when [:huge, "for_version_up"],
             [:huge, "default"]
            huge_data
        else
            {}
        end
    end

    def std_data
        {
            id:       id,
            title:    title,
            fulltext: "",
        }
    end

    def huge_data
        {
            id:       id,
            title:    title,
            fulltext: get_external_file_text,
        }
    end

`std_data` や `huge_data` は AreSearch のAPIではない。
委譲先のメソッド名や分け方は利用側で自由に決められる。

`are_search_indexable?` も index_target_name と sync_stage_name を受け取る。
デフォルトは true。

    def are_search_indexable?(index_target_name, sync_stage_name)
        case [index_target_name, sync_stage_name]
        when [:default, "default"]
            published?
        when [:default, "with_external_file"]
            published? && external_file_attached?
        else
            true
        end
    end

trueではない場合、そのstageの同期時にドキュメントをdeleteする。
同じIndexTargetの別stageが後からindexすれば、そのstageの判定とdataで再作成される。


# 8. stage の前後処理
================================================================

stage間の待機条件は `are_search_before_sync_check` で指定できる。
デフォルトは true。

    def self.are_search_before_sync_check(ar_instance_key, index_target, sync_request)
        if sync_request.sync_stage_name == "with_external_file"
            return are_search_sync_request_exists?(
                ar_instance_key,
                index_target,
                "default",
            ) == false
        end

        true
    end

falseを返した場合、その要求は削除されず、ES同期回数とcallback回数も増えない。
後続のrake回収で再度判定される。

同期後に次の要求を作る場合は `are_search_after_sync_callback` を使用できる。
デフォルトは何もしない。

    def self.are_search_after_sync_callback(record, index_target, sync_request)
        return if record.nil?
        return unless sync_request.sync_stage_name == "default"

        record.are_search_upsert_sync_request(
            index_target,
            "with_external_file",
        )
    end

このcallbackはElasticsearch同期後、現在のSyncRequestを完了させる前に実行される。
callbackで例外が発生した場合、現在のSyncRequestは残り、次回はES同期から再実行される。

`are_search_upsert_sync_request` は要求を作るだけで、その場でJob登録や直接同期は開始しない。
作成したstageは `are_search:run_sync_requests` などで回収する。

force同期は補助処理のため、ES同期だけを行い、`are_search_after_sync_callback` は実行しない。

stageのArray順だけでは実行完了順は保証されない。
順序が必要な場合は、before check、after callback、rakeのstage分離を組み合わせる。


# 9. reindex で使用するstage
================================================================

reindexは、1つのIndexTargetに対して1つのstageを使用する。
全stageを順番に実行する処理ではない。
Searchable を継承した子クラスからは実行できないため、継承系統の最上位モデルの IndexTarget で実行する。

`are_search_all_sync_stage_names` の先頭stageを使う。

    result = Article
        .are_search_index_target(:default)
        .are_search_reindex(stage_position: :first)

末尾stageを使う。

    result = Article
        .are_search_index_target(:default)
        .are_search_reindex(stage_position: :last)

選択したstageの `are_search_index_data` で全レコードの完成ドキュメントを作成する。

`are_search:reindex_all_for_es_version_up` は、各IndexTargetの `:last` stageを使用する。
そのため、最終状態を作るstageを `are_search_all_sync_stage_names` の末尾に置く。


# 10. rake でstageを回収する
================================================================

生成される `lib/tasks/are_search_run_sync_requests.rake` は、処理するstageを引数で指定する。

単一stage。

    bundle exec rake 'are_search:run_sync_requests[default]'

複数stage。

    bundle exec rake 'are_search:run_sync_requests[default,with_external_file]'

引数を省略すると実行しない。
指定したstage名が、どのSearchableモデルにも定義されていない場合は `ArgumentError` を送出する。

stage指定は、モデルやIndexTargetを限定せず、SyncRequestのsync_stage_nameで絞り込む。
同じstage名を複数モデル・targetで使用している場合、それらをまとめて回収する。

重いstageを別の時間帯に処理する場合は、stageごとに定期実行を分ける。

    bundle exec rake 'are_search:run_sync_requests[default]'
    bundle exec rake 'are_search:run_sync_requests[with_external_file]'

通常同期とforce同期の対象scopeは、生成されたrakeファイルで利用側の運用に合わせて変更できる。


# 11. 最小構成
================================================================

単一target・単一stageなら、次の定義だけでよい。

    def self.are_search_index_mappings
        {
            default: {
                index_settings: {
                    max_result_window: 2_000,
                },
                properties: {
                    id:    { type: "long" },
                    title: { type: "text" },
                },
            },
        }
    end

    def self.are_search_all_sync_stage_names
        {
            default: ["default"],
        }
    end

    def are_search_index_data(index_target_name, sync_stage_name)
        case [index_target_name, sync_stage_name]
        when [:default, "default"]
            {
                id:    id,
                title: title,
            }
        else
            {}
        end
    end

`are_search_sync_stage_names_on_enqueue` と `are_search_sync_stage_names_on_after_commit` は省略できる。
省略時はどちらも全stageを対象にする。
