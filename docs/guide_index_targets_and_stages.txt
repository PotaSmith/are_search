================================================================
AreSearch IndexTarget・sync stage ガイド
================================================================

このガイドは、IndexTarget と sync stage をどう分け、どの stage を保存時・after_commit・reindex・rake で使うかを扱う。
導入は guide_setup.txt、検索は guide_usage.txt、運用操作は guide_operations.txt、設定一覧は guide_reference.txt を参照する。


# 1. IndexTarget と sync stage の使い分け
================================================================

AreSearch では同期先とデータ生成経路を分けて考える。

    IndexTarget
        Elasticsearch の alias、mappings、index_settings、検索用途を表す。

    sync stage
        同じ IndexTarget へ投入する完成ドキュメントの生成経路を表す。

判断基準。

    別の mappings、analyzer、検索入口、切り替え対象にしたい
        IndexTarget を分ける。

    同じ index だが、データ生成の時期や取得元を分けたい
        sync stage を分ける。

stage は部分更新のフィールド集合ではない。
各stageの are_search_index_data は、そのstageで保存するドキュメント全体を返す。


# 2. IndexTarget を定義する
================================================================

IndexTarget は are_search_index_mappings の index_target_name ごとに作成される。

    def self.are_search_index_mappings
        {
            default: {
                index_settings: {
                    max_result_window: 2_000,
                },
                properties: {
                    id:    { type: "long" },
                    title: { type: "text" },
                },
            },
            autocomplete: {
                index_settings: {
                    max_result_window: 2_000,
                },
                properties: {
                    id:         { type: "long" },
                    title_edge: { type: "text" },
                },
            },
        }
    end

IndexTarget を取得する。

    default_index = Article.are_search_index_target(:default)
    autocomplete_index = Article.are_search_index_target(:autocomplete)

1つのモデルに複数targetを定義すると、targetごとに次が分かれる。

    mappings
    index_settings
    aliasと物理index
    reindex
    sync request
    検索入口

検索改善のために mappings や analyzer を変更する場合は、使用中targetを直接変更するだけでなく、
新しいtargetを追加して新旧indexを並行同期し、検索入口を切り替える方法を選べる。

STI では同じ Searchable 継承系統の上位モデルが定義した IndexTarget を使用する。
Searchable を継承した子クラスから reindex や BulkIndexer を実行しない。


# 3. sync stage を定義する
================================================================

sync stage は、同じ IndexTarget へ投入するデータ生成経路を識別する。

    "default"
    "with_external_file"

例えば、通常のDBカラムだけで作るstageと、外部ファイルを読み込むstageを分けられる。

    def are_search_index_data(index_target_name, sync_stage_name)
        case [index_target_name, sync_stage_name]
        when [:default, "default"]
            {
                id:       id,
                title:    title,
                fulltext: "",
            }
        when [:default, "with_external_file"]
            {
                id:       id,
                title:    title,
                fulltext: get_external_file_text,
            }
        else
            {}
        end
    end

どちらのstageも完成ドキュメント全体を返す。
同じstage名を複数targetで使うことはできる。


# 4. 使用可能な全stageを指定する
================================================================

全stageを are_search_all_sync_stage_names で定義する。このメソッドは必須。

    def self.are_search_all_sync_stage_names
        {
            default: ["default", "with_external_file"],
            autocomplete: ["default"],
        }
    end

Array の順序は reindex で :first または :last を選ぶときに使用する。
stage間の実行順を必要とする場合は、後述する before check / after callback または rake のstage分離を使用する。

運用中にstageを削除する場合は、そのstageの既存SyncRequestが残っていないことを確認してから行う。


# 5. 保存時にSyncRequestを作るstageを選ぶ
================================================================

保存・touch・削除時に sync request を作成するstageを are_search_sync_stage_names_on_enqueue で指定する。
省略した場合は are_search_all_sync_stage_names と同じ設定を使用する。

全stageの要求を作る場合は定義不要。
一部だけ作る場合。

    def self.are_search_sync_stage_names_on_enqueue
        {
            default: ["default"],
            autocomplete: ["default"],
        }
    end

制約。

    are_search_all_sync_stage_names の部分集合
    targetを省略した場合、そのtargetでは保存時に要求を作らない
    空Arrayを指定した場合も、そのtargetでは要求を作らない


# 6. after_commit で開始するstageを選ぶ
================================================================

commit後に直接同期またはJob登録を開始するstageを are_search_sync_stage_names_on_after_commit で指定する。
省略した場合は are_search_all_sync_stage_names と同じ設定を使用する。

    def self.are_search_sync_stage_names_on_after_commit
        {
            default: ["default"],
            autocomplete: ["default"],
        }
    end

制約。

    are_search_sync_stage_names_on_enqueue の部分集合
    targetを省略した場合、そのtargetではafter_commitから同期を開始しない
    空Arrayを指定した場合も、そのtargetでは同期を開始しない

開始方法は AreSearch.after_commit_mode に従う。詳細は guide_reference.txt を参照する。

重いstageをrakeへ残したい場合は、enqueue対象には含め、after_commit対象から外す。


# 7. stage ごとの投入データを定義する
================================================================

are_search_index_data の基本仕様は guide_reference.txt を参照する。
stage ごとにデータ生成を分ける例。

    def are_search_index_data(index_target_name, sync_stage_name)
        case [index_target_name, sync_stage_name]
        when [:default, "default"]
            {
                id:       id,
                title:    title,
                fulltext: "",
            }
        when [:default, "with_external_file"]
            {
                id:       id,
                title:    title,
                fulltext: get_external_file_text,
            }
        else
            {}
        end
    end


分岐が多くなる場合は、are_search_index_data を分岐だけにしてデータ生成を通常のモデルメソッドへ分けられる。

    def are_search_index_data(index_target_name, sync_stage_name)
        case [index_target_name, sync_stage_name]
        when [:default, "default"]
            std_data
        when [:huge, "for_version_up"],
             [:huge, "default"]
            huge_data
        else
            {}
        end
    end

    def std_data
        {
            id:       id,
            title:    title,
            fulltext: "",
        }
    end

    def huge_data
        {
            id:       id,
            title:    title,
            fulltext: get_external_file_text,
        }
    end

std_data や huge_data は AreSearch のAPIではない。利用側で自由に命名できる。


# 8. target・stage ごとに index 対象を制御する
================================================================

対象レコードを target・stage ごとに index するか切り替える場合は are_search_indexable? を使用する。
詳細は guide_reference.txt を参照する。


# 9. stage の前後条件を指定できる
================================================================

stage間の待機条件が必要な場合は are_search_before_sync_check を使用する。
デフォルトは true。

    def self.are_search_before_sync_check(ar_instance_key, index_target, sync_request)
        if sync_request.sync_stage_name == "with_external_file"
            return are_search_sync_request_exists?(
                ar_instance_key,
                index_target,
                "default",
            ) == false
        end

        true
    end

一時的に同期を待機させたい場合は false を返す。後続の run_sync_requests で再判定されるため、待機条件として利用できる。

同期完了後に別stageの要求を作る場合は are_search_after_sync_callback を使用する。
デフォルトは何もしない。

    def self.are_search_after_sync_callback(record, index_target, sync_request)
        return if record.nil?
        return unless sync_request.sync_stage_name == "default"

        record.are_search_upsert_sync_request(
            index_target,
            "with_external_file",
        )
    end

are_search_upsert_sync_request で作成したstageは are_search:run_sync_requests などで回収する。
force同期は異常中断時の補助処理として使用し、stage連鎖を進める用途には使用しない。


# 10. sync stage の新しい同期処理を開始させない
================================================================

特定の sync stage で新しい同期処理を開始させない場合は sync stage sync lock を使用する。

    index_target = Article.are_search_index_target(:default)

    index_target.are_search_acquire_sync_stage_lock!(
        "with_external_file",
    )

この lock がある間、その IndexTarget の指定stageでは新しい同期処理を開始しない。
他のstageの同期開始と検索には影響しない。

解除する。

    index_target.are_search_release_sync_stage_lock!(
        "with_external_file",
    )

処理中だけsync lockを取得するblock形式の操作は guide_operations.txt を参照する。
AreSearch.index_operation_enabled = true が必要。


# 11. reindex で使用するstageを選ぶ
================================================================

reindex は1つの IndexTarget に対して1つのstageを使用する。
stage_position: :first は先頭stage、:last は末尾stageを使用する。

are_search:reindex_all_for_es_version_up は各IndexTargetの末尾stageを使用するため、
最終状態を作るstageを are_search_all_sync_stage_names の末尾に置く。

reindex の実行方法は guide_operations.txt を参照する。


# 12. rake でstageを分けて回収する
================================================================

are_search:run_sync_requests は指定したstage名で要求を回収する。
同じstage名を複数モデル・targetで使用している場合、それらは同じ実行で回収される。

stageごとの回収実行方法は guide_operations.txt を参照する。


# 13. 最小構成
================================================================

単一target・単一stageなら次の定義だけでよい。

    def self.are_search_index_mappings
        {
            default: {
                index_settings: {
                    max_result_window: 2_000,
                },
                properties: {
                    id:    { type: "long" },
                    title: { type: "text" },
                },
            },
        }
    end

    def self.are_search_all_sync_stage_names
        {
            default: ["default"],
        }
    end

    def are_search_index_data(index_target_name, sync_stage_name)
        case [index_target_name, sync_stage_name]
        when [:default, "default"]
            {
                id:    id,
                title: title,
            }
        else
            {}
        end
    end

are_search_sync_stage_names_on_enqueue と are_search_sync_stage_names_on_after_commit は省略できる。
省略時はどちらも全stageを対象にする。
