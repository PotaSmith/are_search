================================================================
AreSearch 使い方ガイド
================================================================

このファイルは、検索方法と SearchResult の扱いを説明する。
導入手順は guide_setup.txt、IndexTargetとsync stageは guide_index_targets_and_stages.txt、
管理操作は guide_operations.txt を参照する。


# 1. 検索入口
================================================================

AreSearch::Searcher.search に index target の Array と検索オプションを指定する。

    article_index = Article.are_search_index_target(:default)

    result = AreSearch::Searcher.search(
        [article_index],
        queries: [
            {
                query_string: "検索ワード",
                fields:       [:title, :body],
            },
        ],
    )

戻り値は AreSearch::SearchResult。


## 1-1. 単一 target のショートハンド
----------------------------------------------------------------

IndexTarget#are_search_search は、単一 target 検索用のショートハンド。

    result = article_index.are_search_search(
        "検索ワード",
        fields: [:title, :body],
    )

relation を指定できる。


# 2. 検索方式
================================================================

## 2-1. 標準検索
----------------------------------------------------------------

queries は1件以上の Array で指定する。
各要素には query_string と fields が必要。query_type は省略できる。
query_string が空文字列または空白だけの場合、その条件は検索に使用されない。

検索条件が1件の場合。

    result = AreSearch::Searcher.search(
        [article_index],
        queries: [
            {
                query_string: "Rails",
                fields:       [:title, :body],
            },
        ],
    )

複数条件は queries に複数要素を指定する。
すべての条件を満たす文書を検索する。

    result = AreSearch::Searcher.search(
        [article_index],
        queries: [
            {
                query_string: "Rails",
                fields:       [:title, :body],
            },
            {
                query_string: "Elasticsearch",
                fields: {
                    title: 2.0,
                    body:  1.0,
                },
            },
        ],
    )

fields は text 型フィールドの Array、または boost を値に持つ Hash で指定する。

    fields: [:title, :body]

    fields: {
        title: 2.0,
        body:  1.0,
    }

フィールド名は Symbol。boost は0より大きい Integer または Float。
text 型以外のフィールドは指定できない。

query_type の既定値は combined_fields。
空白で区切られた検索語を AND 条件として検索する。

    query_type: AreSearch.query_type_combined_fields

simple_query_string の指定例。

    queries: [
        {
            query_string: 'Ruby + (Rails | Elasticsearch) -"Java VM"',
            fields:       [:title, :body],
            query_type:   AreSearch.query_type_simple_query_string,
        },
    ]

使用できる主な検索式。

    Ruby Rails
        default_operatorがANDのため、両方を含む

    Ruby + Rails
        AND

    Ruby | Rails
        OR

    Ruby -Rails
        NOT

    Ruby + (Rails | Elasticsearch)
        括弧による優先順位

    "Ruby on Rails"
        フレーズ検索

query_string は変換せず Elasticsearch へ渡す。
指定の詳細は Elasticsearch の simple_query_string のドキュメントを参照する。

query_type は次の定数のいずれかを指定する。

    AreSearch.query_type_combined_fields
    AreSearch.query_type_simple_query_string


## 2-2. More Like This
----------------------------------------------------------------

mlt は、指定したレコードに似たレコードを検索する。
queries、sort とは同時に指定できない。

    result = AreSearch::Searcher.search(
        [article_index],
        mlt: {
            fields: [:title, :body],
            like: {
                instance:     article,
                index_target: article_index,
            },
            min_term_freq:        1,
            min_doc_freq:         2,
            max_query_terms:      20,
            min_word_length:      2,
            minimum_should_match: "30%",
            boost_terms:          1.5,
        },
    )

mlt.fields と mlt.like は必須。

mlt.fields は More Like This で使用するフィールドを Symbol のArrayで指定する。
検索対象側では、1つ以上のIndexTargetに存在し、同名フィールドが別の型で定義されていない
text または keyword 型フィールドを使用できる。

mlt.fields は mlt.like.index_target の基準ドキュメントのフィールドとしても使用する。
mlt.like.index_target の場合、型だけでなく `_source` または `store: true` に設定されている必要がある。

mlt.like は基準ドキュメントを指定する。
mlt.like の instance、index_target は必須。

    instance
        基準レコード。

    index_target
        基準レコードが保存されている IndexTarget。
        instance から同じtargetを解決したときに、同じElasticsearch aliasを指す必要がある。

`_source` から mlt.fields を取得する場合。

    _source: {
        includes: [:title],
    },
    properties: {
        title: { type: "text" },
    }

`store: true` から mlt.fields を使用する場合。

    properties: {
        body: {
            type:  "text",
            store: true,
        },
    }

mlt.fields と like 以外の Symbol key は、内容をチェックせずElasticsearchへ渡す。
min_term_freq、min_doc_freq、max_query_terms の既定値は、それぞれ 2、5、25。


## 2-3. Raw body 検索
----------------------------------------------------------------

raw_body に Elasticsearch の Query DSL を指定する。

    body = {
        track_total_hits: true,
        query: {
            bool: {
                must: [
                    { match: { title: "Rails" } },
                ],
            },
        },
    }

    result = AreSearch::Searcher.search(
        [article_index],
        raw_body: body,
        page:     1,
        per_page: 20,
    )

raw_body と同時に使用できる AreSearch 側のオプション。

    :model_relations
    :page
    :per_page
    :build_model_bool
    :enable_runtime_mappings
    :dump_body

from と size は page / per_page から設定する。
その他の指定は変換せず Elasticsearch へ渡す。元の Hash は変更しない。

build_model_bool: true を指定すると検索対象モデルの条件を追加する。
raw_body には query.bool が必要。Symbol と String の key を使用できる。

    result = AreSearch::Searcher.search(
        [article_index],
        raw_body: {
            query: {
                bool: {
                    must: [
                        { match: { title: "Rails" } },
                    ],
                },
            },
        },
        build_model_bool: true,
    )

正確な総件数が必要な場合は track_total_hits: true を指定する。
生レスポンスは result.raw_response で返す。


# 3. 共通オプション
================================================================

標準検索と More Like This で使用できる共通オプション。

    :runtime_mappings
    :where
    :where_not
    :where_or
    :aggs
    :page
    :per_page
    :model_relations
    :highlight
    :response
    :enable_runtime_mappings
    :dump_body

sort は標準検索でのみ使用できる。

単一 target のショートハンドでは relation、Searcher.search では model_relations を使用する。

フィールドの条件。

    queries.fields
        1つ以上の target に存在し、同名フィールドが別の型で定義されていない text フィールド。

    mlt.fields
        1つ以上の検索対象 target に存在し、同名フィールドが別の型で定義されていない
        text または keyword フィールド。
        mlt.like.index_target にも同名の text または keyword フィールドが存在し、
        `_source` に保存されているか、mappingで `store: true` を指定している必要がある。

    highlight.fields
        1つ以上の target に存在し、同名フィールドが別の型で定義されていない
        text または keyword フィールド。

    where / where_not / where_or
        1つ以上の target に存在し、同名フィールドが text 型として定義されていないフィールド。

    sort
        すべての target に存在する非 text フィールド。

    aggs
        1つ以上の target に存在し、同名フィールドが text 型として定義されていないフィールド。

runtime_mappingsで定義したフィールドは、typeに応じてpropertiesと同じ条件で判定する。
同名のpropertiesがある場合は、runtime fieldのtypeを優先する。

標準検索オプションの通常フィールド名は、各 target の properties 直下に定義された Symbol に限る。
runtime_mappingsのフィールド名は、そのHash直下のSymbolを使用する。
response.source、response.fields、response.stored_fields、
response.docvalue_fieldsはmappingとの照合を行わない。


## 3-1. runtime_mappings
----------------------------------------------------------------

検索時だけ使用するruntime fieldを指定する。

    result = AreSearch::Searcher.search(
        [article_index],
        runtime_mappings: {
            runtime_status: {
                type: "keyword",
                script: {
                    source: "emit('published')",
                },
            },
        },
        queries: [
            {
                query_string: "Rails",
                fields:       [:title],
            },
        ],
        where: {
            runtime_status: {
                term: "published",
            },
        },
        response: {
            fields: ["runtime_status"],
        },
        enable_runtime_mappings: true,
    )

runtime_mappingsは1件以上のruntime fieldを持つHashで指定する。
runtime field名と各field定義のkeyはSymbolを使用し、typeはStringまたはSymbolで必ず指定する。
type以外の値は変更せずElasticsearchへ渡す。

runtime_mappingsを使用する場合は、Searcher.searchのトップレベルに
`enable_runtime_mappings: true`を指定する。
ただし、dump_body: true の場合は、enable_runtime_mappings の指定有無を検査しない。
runtime_mappingsは検索body policyの検査対象から除外され、それ以外のbodyは通常どおり検査される。

raw_body検索ではruntime_mappingsをraw_body内へ指定し、
`enable_runtime_mappings: true`はSearcher.searchのトップレベルへ指定する。


## 3-2. response
----------------------------------------------------------------

検索結果へ追加で含める_sourceとfields系の取得方法を指定する。

    response: {
        source: [
            "title",
            "payload.display.*",
        ],
        fields: [
            "runtime_status",
            "published_at",
        ],
        stored_fields: [
            "body",
        ],
        docvalue_fields: [
            "status",
            "user_id",
        ],
    }

source未指定時は、ActiveRecordの復元に必要な予約フィールドだけを_sourceから取得する。
指定したsource pathは予約フィールドへ追加される。

source、fields、stored_fields、docvalue_fieldsはStringのArrayで指定する。
propertiesやmappingの _source.includes / excludes、store、doc_valuesとの照合は行わない。

source
    Elasticsearchの_sourceから取得する。
    indexの _source に保存されていない値は含まれない。

fields
    Elasticsearchのfieldsへそのまま指定する。
    通常のmapping fieldはElasticsearchが _source から値を取得するため、
    indexの _source に保存されていない値は含まれない。
    runtime fieldは _source に保存されていなくても取得できる。

stored_fields
    Elasticsearchのstored_fieldsへそのまま指定する。
    mappingでstore: trueになっているフィールドを _source とは別に取得する。
    storeされていないフィールドを指定した場合の扱いはElasticsearchに委ねる。

docvalue_fields
    Elasticsearchのdocvalue_fieldsへそのまま指定する。
    keyword、数値、date等のdoc valuesを利用できるフィールドを _source とは別に取得する。
    doc valuesを利用できないフィールドを指定した場合の扱いはElasticsearchに委ねる。

fields、stored_fields、docvalue_fieldsで返された値は、いずれもrecords_with_hitの
hit[:fields]から取得する。

raw_body検索ではresponseを使用せず、_source、fields、stored_fields、
docvalue_fieldsをbodyへ直接指定する。


## 3-3. 外部入力として使用する値
----------------------------------------------------------------

外部入力として指定できる値。

    queries の query_string
    where / where_not / where_or の条件値
    page

各オプションの型と制約が適用される。
標準の search_param_policy では、queries.query_string は2048文字まで、
where / where_not / where_or の term、terms、range の各値は256文字まで許可する。
terms は各要素、range は各比較値を個別に検査する。
この制限は `AreSearch.search_param_policy` で差し替えできる。

これらの値が制約に合わない場合、search_failure_mode が :empty_result なら検索を実行せず、
STATUS_PARAMS_INVALID の空結果を返す。:raise なら AreSearch::InvalidSearchOption を送出する。
page は正の Integer で指定する。page と per_page から算出した開始位置が max_result_window 以上の場合も、
検索を実行せず同じ検索パラメータ不正として扱う。


検索条件が1件の場合。

    result = AreSearch::Searcher.search(
        [article_index],
        queries: [
            {
                query_string: params[:q],
                fields:       [:title, :body],
            },
        ],
    )

検索条件が複数ある場合。

    result = AreSearch::Searcher.search(
        [article_index],
        queries: [
            {
                query_string: params[:title_q],
                fields:       [:title],
            },
            {
                query_string: params[:body_q],
                fields:       [:body],
            },
        ],
    )

絞り込み。

    result = AreSearch::Searcher.search(
        [article_index],
        queries: [
            {
                query_string: params[:q],
                fields:       [:title, :body],
            },
        ],
        where: {
            status: {
                term: params[:filter_value],
            },
        },
    )

並び順、ページング。

    result = AreSearch::Searcher.search(
        [article_index],
        queries: [
            {
                query_string: params[:q],
                fields:       [:title, :body],
            },
        ],
        sort:         :updated_at,
        page:         params.fetch(:page, 1).to_i,
        per_page:     20,
    )

# 4. where / where_not / where_or
================================================================

where、where_not、where_or は Hash または Array<Hash> で指定する。
各フィールドには term、terms、range のいずれか1つを指定する。

    where: {
        status: {
            term: "published",
        },
        user_id: {
            terms: [1, 2, 3],
        },
        price: {
            range: {
                gte: 1_000,
                lte: 5_000,
            },
        },
    }

同じ field の条件を複数指定する場合は Array を使用する。

    where: [
        {
            price: {
                range: {
                    gte: 1_000,
                },
            },
        },
        {
            price: {
                range: {
                    lte: 5_000,
                },
            },
        },
    ]

    where_not: {
        status: {
            terms: ["draft", "deleted"],
        },
    }

    where_or: [
        {
            status: {
                term: "featured",
            },
        },
        {
            user_id: {
                terms: [1, 2, 3],
            },
        },
    ]

text 型フィールドは指定できない。
where はすべて一致、where_not は除外、where_or はいずれか1件一致の条件になる。

term、terms、range の値は String、Integer、Float、true、false。
terms は Array、range は1件以上の Hash で指定する。terms には空の Array も指定できる。
日付は Elasticsearch が解釈できる String または Integer で指定する。


# 5. model_relations
================================================================

検索結果を ActiveRecord から取得する Relation を、対象モデルごとに指定する。

    result = AreSearch::Searcher.search(
        [
            Article.are_search_index_target(:default),
            Document.are_search_index_target(:default),
        ],
        queries: [
            {
                query_string: "Rails",
                fields:       [:title, :body],
            },
        ],
        model_relations: {
            Article => Article
                .where(status: "published")
                .includes(:user, :tags),
            Document => Document
                .where(visible: true)
                .includes(:author),
        },
    )

単一 target のショートハンドでは relation を使用できる。

    result = article_index.are_search_search(
        "Rails",
        fields: [:title, :body],
        relation: Article
            .where(status: "published")
            .includes(:user, :tags),
    )

model_relations の key は検索対象モデル、値は ActiveRecord::Relation。
Relation の klass は key のモデルと同じクラスである必要がある。
Relation の条件に合わない結果と、DB に存在しない結果は除外される。
includes、joins なども Relation に指定できる。


# 6. page / per_page
================================================================

    result = AreSearch::Searcher.search(
        [article_index],
        queries: [
            {
                query_string: "Rails",
                fields:       [:title, :body],
            },
        ],
        page:         2,
        per_page:     20,
    )

result.records は Kaminari の paginate ヘルパーに対応する。

    paginate result.records

主なページ情報。

    result.records.page
    result.records.per_page
    result.records.total_count
    result.records.es_total_count
    result.records.pagination_total_count
    result.records.total_pages

page と per_page は正の Integer。
取得範囲の上限は target の max_result_window。複数 target では最小値を使用する。
page と per_page から算出した開始位置が max_result_window 以上の場合は検索パラメータ不正になる。
開始位置が上限未満で、要求件数が上限を超える最後のページでは、Elasticsearch へ渡す size を縮小する。

件数は用途ごとに分かれる。

    es_total_count
        Elasticsearch が返した検索ヒット総数。

    total_count
        es_total_count から、現在ページでActiveRecordへ復元できなかった件数を差し引いた表示用総件数。

    pagination_total_count
        es_total_count と max_result_window の小さい方から、現在ページでActiveRecordへ復元できなかった件数を差し引いた
        ページング可能件数。

total_pages、previous_page、next_page、out_of_range? などのページ判定は pagination_total_count を使用する。
Kaminari の page_entries_info が参照する total_count は表示用総件数を返す。


# 7. sort
================================================================

sort は標準検索で使用できる。

    sort: :updated_at

    sort: {
        updated_at: :desc,
        id:         :desc,
    }

Hash はキーの記述順を優先順位として使用する。
フィールドには、Elasticsearch の特別な値として _score と _doc も指定できる。

sort の値は String または Symbol。指定の詳細は Elasticsearch のドキュメントを参照する。


# 8. aggs
================================================================

非textフィールドを aggregation に使用する。
フィールド名だけを指定する場合は Array を使用する。

    aggs: [:status, :category]

各フィールドは、フィールド名と同名の terms aggregation へ変換する。
size には AreSearch.default_aggs_size の値を使用する。デフォルト値は200。

集計名やオプションを指定する場合は Elasticsearch 形式の Hash を使用する。

    aggs: {
        status_count: {
            terms: {
                field: :status,
                size: 20,
            },
        },
        score_ranges: {
            range: {
                field: :score,
                ranges: [
                    { to: 1.0 },
                    { from: 1.0, to: 2.0, key: "middle" },
                    { from: 2.0 },
                ],
            },
        },
    }

集計名と aggregation 種別は Symbol。aggregation body の field は必須。
検索オプションの検査では aggregation 種別を限定せず、field が非textフィールドであることだけを確認する。その他の指定は変更せず Elasticsearch へ渡す。

    result.aggs(:status_count).each do |name, count|
        puts "#{name}: #{count}"
    end

result.aggs(name) は Array 形式の buckets を簡易化して返す。

    key がある
        [[key, doc_count], ...]
        key_as_string がある場合は key の代わりに使用する。

    key がない
        [doc_count, ...]

対象 aggregation が無い、buckets が無い、または Array 形式でない場合は空 Array を返す。
引数なしの result.aggs は内部の key を使用した結果全体を Hash で返す。
簡易結果の対象外になる場合は result.raw_response を参照する。


# 9. highlight
================================================================

highlight は検索結果の一致部分を返す。
fields は必須で、text または keyword 型フィールドを指定する。

フィールド名だけを指定する場合。

    highlight: {
        fields: [:title, :body, :status],
    }

フィールド別オプションを指定する場合。

    highlight: {
        fields: {
            body: {
                fragment_size:       200,
                number_of_fragments: 3,
            },
            status: {
                number_of_fragments: 0,
            },
        },
        type:                "unified",
        require_field_match: false,
    }

fields は Array または Hash で指定する。Array は空のフィールド別オプションを持つ Hash へ変換する。
fields に指定するフィールドには store: true が必要。

    body: {
        type:  "text",
        store: true,
    }

検索オプションの検査では fields のフィールドだけを確認し、その他の指定は変更せず Elasticsearch へ渡す。
簡易結果の対象外になる highlight 設定を使用した場合は result.raw_response を参照する。
その他の指定は Elasticsearch の highlighting のドキュメントを参照する。
mapping または index_settings の変更後は reindex が必要。


# 10. dump_body
================================================================

検索を実行せず、AreSearch が組み立てた body を返す。

    body = AreSearch::Searcher.search(
        [article_index],
        queries: [
            {
                query_string: "Rails",
                fields:       [:title, :body],
            },
        ],
        where: {
            status: {
                term: "published",
            },
        },
        dump_body: true,
    )

    pp body

raw_body 検索では、page、per_page、build_model_bool を反映した body を返す。


# 11. SearchResult
================================================================

## 11-1. status
----------------------------------------------------------------

検索の終了状態を返す。

    result.status

status は SearchResult の定数で判定する。

    if result.status == AreSearch::SearchResult::STATUS_PARAMS_INVALID
        # 外部入力値が不正、または SearchBodyPolicy に拒否された場合の処理
    end

戻り値。

    AreSearch::SearchResult::STATUS_OK
        値は :ok。
        Elasticsearch へ検索を実行した。
        検索結果が0件の場合もこのstatusになる。

    AreSearch::SearchResult::STATUS_PARAMS_INVALID
        値は :params_invalid。
        外部入力として使用する値が制約に合わない、または SearchBodyPolicy が検索bodyを拒否したため、
        検索を実行せず空結果を返した。

    AreSearch::SearchResult::STATUS_INDEX_NOT_FOUND
        値は :index_not_found。
        検索対象 index、または More Like This の mlt.like.index_target の alias が存在しないため、
        検索を実行せず空結果を返した。


## 11-2. records
----------------------------------------------------------------

    result.records

ActiveRecord のレコードを検索順で返す。


## 11-3. records_with_hit
----------------------------------------------------------------

ActiveRecord のレコードと、対応する Elasticsearch hit の情報を検索順で返す。

    result.records_with_hit.each do |record, hit|
        puts record.title
        puts hit[:index]
        puts hit[:id]
        puts hit[:index_target_name]
        puts hit[:source][:title]
        puts hit[:fields][:runtime_status]

        hit[:highlight].each do |field_name, fragments|
            fragments.each do |fragment|
                puts "#{field_name}: #{fragment}"
            end
        end
    end

hit は次のキーを持つ。

    :index
        Elasticsearch が返した _index。

    :id
        Elasticsearch が返した _id。

    :source
        Elasticsearch が返した _source。
        フィールド名は Symbol。対象 hit に値が無い場合は空 Hash。

    :fields
        Elasticsearch が返した fields。
        response.fields、response.stored_fields、response.docvalue_fieldsで取得した値を含む。
        フィールド名は Symbol。値のArrayは変更しない。
        対象 hit に値が無い場合は空 Hash。

    :highlight
        Elasticsearch が返した highlight。
        フィールド名は Symbol。対象 hit に値が無い場合は空 Hash。

    :index_target_name
        レコードを復元した IndexTarget の index_target_name。

1件でも _source が無い場合、ActiveRecord への復元は行わず、records と records_with_hit は空になる。
Elasticsearch のレスポンスは raw_response に残り、総件数は records.es_total_count で確認できる。
